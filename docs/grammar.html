Formal grammar

The EBNF definition of SPL 1.0. If the prose and the grammar disagree about syntax, the grammar wins; the prose is authoritative for meaning.

Message format

  • Single-statement block – $> followed by a statement on the same line. It ends with that statement, including its indented body. Consecutive $> lines are independent blocks.
  • Multi-line block – $> alone on its line, statements, ended by <$. Allows blank lines, multi-line JSON and indented control flow. If <$ is omitted the block extends to the end of the message.
  • $> and <$ are recognized only outside quoted strings.
  • Parameters use {param=value, …}; JSON object literals use quoted keys and :.

EBNF

message     = { prose | block } ;
block       = "$>" statement                              (* single-statement *)
            | "$>" NEWLINE { statement } [ "<$" ] ;       (* multi-line *)
body        = INDENT statement { statement } DEDENT ;

statement   = let | reset | constraint | assert | fail | out | elicit | think
            | if | while | for | break | continue | def | return | yield | try
            | tool_call | func_call ;

let         = "let" VAR "=" value ;
reset       = "reset" ( VAR | "*" ) ;
constraint  = ( "enforce" | "forbid" ) [ params ] STRING ;
assert      = "assert" cond "->" STRING ;
fail        = "fail" STRING ;
out         = "out" [ params ] STRING ;
elicit      = "elicit" [ params ] STRING ;
think       = "think" [ params ] STRING ;
if          = "if" cond ":" body [ "else" ":" body ] ;
while       = "while" [ params ] cond ":" body ;
for         = "for" VAR "in" ( expr ".." expr | expr ) ":" body ;
break       = "break" ;   continue = "continue" ;
def         = "def" NAME "(" [ VAR { "," VAR } ] ")" ":" body ;
return      = "return" expr ;   yield = "yield" expr ;
try         = "try" ":" body "on_error" ":" body ;
tool_call   = [ VAR "=" ] NAME params [ STRING ] ;
func_call   = NAME "(" [ expr { "," expr } ] ")" ;

value       = expr | tool_call | out | elicit | func_call | for ;
params      = "{" NAME "=" expr { "," NAME "=" expr } "}" ;

cond        = and { "|" and } ;
and         = not { "&" not } ;
not         = "!" not | "(" cond ")" | semantic | comparison | expr ;
semantic    = "?" STRING ;
comparison  = expr ( "==" | "!=" | "<" | "<=" | ">" | ">=" | "in" ) expr ;

expr        = term { ( "+" | "-" ) term } ;
term        = postfix { ( "*" | "/" ) postfix } ;
postfix     = primary { "[" expr "]" | "." NAME } ;
primary     = literal | VAR | "len" "(" expr ")" | "(" expr ")" ;
literal     = STRING | NUMBER | "true" | "false" | "null" | array | object ;
array       = "[" [ expr { "," expr } ] "]" ;
object      = "{" [ STRING ":" expr { "," STRING ":" expr } ] "}" ;

VAR = "$" IDENT ;   NAME = IDENT ;   STRING = "'" ... "'" | '"' ... '"' ;

Lexical notes

  • Quoting – strings use '…' or "…" with escapes \' \" \\ \$. Unquoted tokens are keywords, variables, operators and identifiers.
  • Comments – # outside a quoted string starts a comment to the end of the line.
  • Precedence – conditions: ! > & > |; expressions: * / > + -.
  • Ranges – a..b is inclusive on both ends.
