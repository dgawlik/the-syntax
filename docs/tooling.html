Tooling & testing

Editor support and the behavioural conformance suite.

VS Code extension

The vscode/ folder contains a TextMate-grammar extension that highlights:

  • .spl files
  • ```spl fenced blocks in Markdown (including ~~~spl and longer fences)

Highlighted: the @{SPL/1} / @{SPL/off} markers, $> … <$ blocks, all statements and control-flow keywords, $variables, {param=value} parameters, tool calls, semantic conditions (?'…'), strings with escapes and interpolation, and # comments. Prose outside blocks is left unstyled; inside a Markdown ```spl fence, bare statements without $> are highlighted too.

Install

A prebuilt package is in the repository. From the vscode/ folder:

code --install-extension spl-language-0.1.0.vsix

Or on Windows run install.ps1.

Build & test

npm install
npm test          # grammar tests
npm run package   # produces spl-language-<version>.vsix

Set the MARKDOWN_GRAMMAR environment variable to VS Code's markdown.tmLanguage.json to run the tests against the real Markdown grammar.

Conformance suite

agent/spl.conformance.md contains behavioural tests for the agent (SPL 1.0). Run it after every spec change to see which edits help or hurt.

How to run

  • Use a fresh session for every case, on the model named in the agent front matter.
  • Multi-turn cases (Turn 1, Turn 2, …) run in one session, in order.
  • Ready-to-paste single-message versions of many cases are in sample-prompts/validation/, named tNN-*.spl.
  • Model output is nondeterministic: run each case 3 times. A [hard] check must pass 3/3; a [soft] check at least 2/3.
  • Record results in the table at the end of the file, with the spec commit hash.

The envelope check used across cases: the entire response parses as JSON with no code fence or other text, and has "spl": "1.0", "status": "failure", a reason string and a statement (string or null).

Limitations

SPL is a prompt notation. The agent file is an instruction prompt, so control flow, state and assertions are model behaviour rather than deterministic execution, and the semantics of len, sch and semantic conditions rely on model judgement. Use the conformance suite to measure how reliably a given model follows the spec.
