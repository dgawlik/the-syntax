Semantic Prompt Language

A lightweight protocol that lets you "script" an LLM's response with pseudo-Python syntax that is easy to read, share and version.

@{SPL/1}

Summarize the project README for a new contributor.

$>
let $topic = 'the README'
try:
    $readme = read{path='README.md'}
on_error:
    fail 'README.md could not be read'
assert $readme != null -> 'README is empty'
out{len='under 5 bullets', fmt='bullet_list'} 'Summarize $topic'
<$

What it is

SPL combines Python-like pseudocode with natural language. Prose outside $> … <$ blocks is ordinary instruction; statements inside blocks declare variables, constraints, control flow, tool calls and output formats. Any capable LLM already understands this style, so the protocol is activated by a single marker, @{SPL/1}, and the agent file in this repository.

What it is for

Long-winded prose prompts are hard to read, review and reuse. SPL establishes a common vocabulary and syntax so that prompts can be:

  • Scannable – constraints (enforce/forbid), output shape (out{…}) and state (let $x) are conspicuous.
  • Reproducible – write once, get similar results every time, with less noise than prose.
  • Shareable – check prompts into Git, track them in a team repository and pass them around as .spl files.

SPL is a prompt notation, not a runtime. There is no parser or evaluator behind it: if, while, assert and friends describe behaviour the model is asked to follow. Results are as deterministic as the model is. See Execution & errors and Tooling & testing for how the behaviour is specified and verified.
