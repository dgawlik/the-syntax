Language reference

Everything in SPL 1.0: values, variables, conditions, constraints, output, control flow, functions and tool calls.

Data types & expressions

SPL has the JSON types: string, number, boolean, array, object and null.

let $name = 'Alice'                         # string
let $age = 30                               # number
let $is_student = true                      # boolean
let $hobbies = ['reading', 'coding']        # array
let $address = {'city': 'Wonderland'}       # object

Expressions may be used wherever a value is expected (let, tool parameters, conditions, yield, return).

OperationNotes
Arithmetic + - * /, parenthesesOn numbers. Division by zero is an execution error.
Concatenation +Two strings or two arrays. Mixing types is an error.
Indexing $list[0]Zero-based. Out of range is an error.
Field access $obj.key, $obj['key']Missing key gives null; accessing a field of a non-object is an error.
len($x)Characters of a string, items of an array, keys of an object.

Interpolation

Both quote styles support interpolation:

SyntaxMeaning
$nameValue of the variable. Strings as-is; numbers, booleans, null, arrays and objects as JSON.
${name}Delimits the name when text follows: '${unit}s'.
${expression}Full expression: ${len($items)}, ${$users[0].name}.
\$Literal dollar sign.

Interpolating an undefined variable is an execution error.

Variables & scope

  • let $x = value declares a variable. The value can be a literal, expression, tool call, out, elicit, function call or for expression.
  • Variables cannot be reassigned: let on an existing name is an error (Cannot reassign $x; use reset first).
  • reset $x removes a session variable (no-op if undefined). reset * removes all session variables. It cannot remove body-scoped variables, functions or constraints.

Scope

  • Session scope – a top-level let (or $x = tool{…}) outside any if/else, while, for or function body persists for the whole conversation.
  • Body scope – variables declared inside a branch, loop or function body live until that body ends (fresh per loop iteration).
  • No shadowing – redeclaring any visible name is an error. Reading an undefined variable is an error (Undefined variable $x).
  • try / on_error bodies are not scopes.
let $total = 3                  # session scope
for $i in 0..2:                 # $i is loop-local
    let $label = 'Item $i'      # recreated each iteration
    out '$label of $total'

Conditions

Conditions in assert, if and while are either:

  1. Semantic – ?'…', a natural-language expression judged by the model (?'requirements are met'). A quoted string without ? is always a string literal.
  2. Deterministic – comparisons == != < <= > >=, membership $item in $collection, null checks $var != null.

Combine with & (AND), | (OR), ! (NOT) and parentheses. Precedence: ! > & > |.

assert ?'inputs are valid' & $retries < 3 -> 'Exceeded maximum retries or inputs invalid'
assert !?'user is blocked' -> 'Operation forbidden for blocked users'
if ($env == 'prod' & !?'emergency override'):
    enforce 'Require two-person review'

Constraints & failures

enforce is a hard requirement the response must satisfy; forbid is something that must never happen. Both accept a scope:

ScopeActive
'session' (default)From the statement until the session ends.
'message'Until the end of the current message.
'block'Until the end of the enclosing body (block, branch or loop iteration).
enforce 'This must be satisfied'
forbid{scope='message'} 'This must not be done'

A constraint is only registered when its statement executes – one inside an untaken branch is never active. If a constraint cannot be satisfied, execution fails and the reason names it.

  • assert <cond> -> 'message' – fails with message if the condition is not met.
  • fail 'message' – fails unconditionally.

Output & interaction

out

out{len=…, fmt=…, sch=…, synth=…} 'prompt' generates a response.

ParamMeaning
lenFree-text length guidance ('one sentence', 'under 5 bullets'). A target, not a hard limit – use enforce for hard limits.
fmtShape of human-readable output: text (default), markdown, sentence, paragraph, bullet_list, code, table.
schData type: string, number, boolean, array, object, json, or a JSON schema.
synthtrue allows merging with neighbouring synth outputs into one passage. Default false.
out{len='about 100 words', fmt='text'} 'Write a joke about programming'
out{sch='array'} 'Generate names of 3 fruits'

Structured output. When sch is anything other than 'string', the output must be the raw value only – valid JSON (or a bare number/boolean), no code fences or commentary. On a schema mismatch the model retries once, then fails with Output did not match sch. A structured output must be the only emitted output of its message (Structured output cannot be combined with other output).

Multiple outputs are emitted in statement order separated by blank lines, each verbatim unless synth=true.

Capture. let $draft = out{sch='string'} 'Draft a title' binds the result and does not add it to the response.

elicit

Asks the user a question and suspends execution until they answer. Optional sch validates the answer (asked again once on mismatch, then fails). While suspended only the question is emitted.

let $age = elicit{sch='number'} 'Please provide your age'

think

think{level=…, show=…} 'prompt' performs deliberate reasoning. level is low (a few sentences), medium or high (thorough). By default (show=true) the reasoning is emitted as a blockquote introduced by Thinking:; with show=false it stays internal. It is not emitted when the message has a structured out.

think{level='high'} 'Consider the implications of the current state'

Control flow

if / else

if $status == 'error' | ?'build is red':
    think{level='high'} 'Find root cause'
    out 'Summarize failure'
else:
    out 'Write success confirmation'

while

Loops while the condition holds, with a default cap of 5 iterations. max overrides the cap; on_max is 'stop' (default, exit and continue) or 'fail' (error while loop exceeded max iterations).

while{max=3, on_max='fail'} ?'tests are failing':
    think 'Evaluate how to fix broken tests'

for

Iterates over a range (inclusive on both ends; a start greater than the end is empty) or an array. break exits the innermost loop, continue skips to the next iteration; both are errors outside a loop.

for $i in 0..4:
    out "Iteration $i"
for $item in $items:
    out "Process $item"

As an expression, for builds an array with yield (a loop with no yield yields []):

let $squares = for $i in 1..3:
    yield $i * $i          # [1, 4, 9]

Functions

def greet($who, $punct):
    out 'Hello $who$punct'
    return len($who)

greet('Alice', '!')
let $n = greet('Bob', '?')
  • Parameters are local and follow the no-shadowing rule; the body can read session variables.
  • return <expr> yields a value; without it the result is null.
  • Function names are defined for the rest of the session and cannot be redefined or reset.
  • Recursion (direct or indirect), wrong argument counts and undefined functions are errors.

Tool invocations

Tools available in the environment are called directly: [$variable =] tool_name{param=value, …} ['guidance']. Typical tools are read, search, execute, edit and vscode; availability is set by the agent's tools list. Calling an unavailable tool is an error (Tool <name> not available).

$matches = search{query='auth_token'} 'Locate authentication token references'
$content = read{path='src/auth.ts'}
execute{command='npm test'} 'Run the full test suite'

Tool errors

A failing tool call is an execution error (Tool <name> failed: <error>) unless wrapped in try/on_error. $error holds the message and is visible only inside on_error. Only tool failures are caught – never assert, fail or constraint violations. A variable declared in try after the failing call is undefined.

try:
    $content = read{path='config.json'}
on_error:
    out 'Config missing: $error'
    let $content = '{}'
